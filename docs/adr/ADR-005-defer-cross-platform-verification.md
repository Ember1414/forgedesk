﻿# ADR-005: 三平台构建与验收降级为"按需触发"

- 状态：已接受（维护者决定）；**2026-10-08 部分修订**——仓库转公开后 macOS 进入发布矩阵（见「执行记录」）
- 日期：2026-09-23
- 关联：ADR-002（两阶段 CI 配额策略）、PLAN §7.0（DoD）、PLAN §15.3（发布前检查清单）、`docs/acceptance/M0.md`

## 上下文

PLAN §7.0 的通用出口标准（DoD）要求每个里程碑"三平台 CI 构建通过，产物可下载安装并启动"。
私有仓库的配额现实是：Actions 每月 2000 分钟，macOS 按 10x、Windows 按 2x 计费，
一次三平台矩阵约消耗 130 配额分钟；而 M0–M2 阶段的应用是空壳与只读 Git 功能，
平台差异集中在 WebView 渲染与打包产物本身，业务逻辑（Rust crate 层）与平台无关
且已被 Linux CI 的全量测试覆盖。三平台矩阵的边际价值在当前阶段远低于其配额成本，
且每个里程碑都被"等人工触发矩阵/盲测"阻塞收口。

## 决策

1. **里程碑收口的默认验证面收窄为**：Linux 质量门禁（CI 全量）+ 本机 Windows
   实测（dev 启动、`pnpm build`、交互级 E2E）+ 全部自动化检查（含 compliance）。
2. **三平台构建矩阵与平台验收改为"按需触发"**，触发时机：
   - 首个对外预发布（M3，按 PLAN §15.3 发布前检查清单）；
   - v1.0 发布验收（M7）；
   - 人工怀疑存在平台相关缺陷时，手动 `workflow_dispatch`（勾选 run_build）。
3. **图标 3 人盲测与布局 3 人盲测**同样并入"首次对外预发布前"执行，
   不再阻塞里程碑收口；此前已完成的单项评审记录保持有效（见 `.github/COMPETITOR-REVIEW.md`）。
4. 打包配置**保持随时可触发状态**：`tauri.conf.json` 持续被 schema 校验，
   产物命名/SHA256SUMS/冒烟脚本就绪，触发成本保持为"打一个 tag"。

## 备选方案

- **维持每里程碑三平台矩阵**：否——按当前推送频率每月额外消耗 500+ 配额分钟，
  两周内耗尽配额的后果（CI 整体不可用）比"晚发现平台回归"严重。
- **夜间三平台矩阵**：否——同样烧配额，且 M0–M2 没有平台敏感逻辑可供它验证。

## 后果

- 正面：配额大幅节省；里程碑收口不再被人工步骤阻塞；"何时看平台差异"变成显式的发布决策。
- 风险与缓解：平台回归可能积累到发布前才暴露——缓解一：打包配置与冒烟脚本保持就绪
  （触发矩阵的边际成本极低）；缓解二：WebKitGTK/ConPTY 类平台问题的排查记录写入
  `docs/DEV-ENV.md` 与（M5 起的）`docs/TROUBLESHOOTING.md`；缓解三：E2E 交互验收
  先行覆盖 DOM 层逻辑，把平台差异压缩到渲染与打包层。
- 对文档的影响：`docs/acceptance/*.md` 中跨平台条目标记"⏸ 延后（ADR-005）"；
  PLAN §7.0 的 DoD 在本项目内的执行口径以本 ADR 为准（AGENTS.md 未定义三平台频率，
  PLAN 的 DoD 表述保持原文不改动，避免篡改计划存档）。

## 执行记录

- 2026-09-23：维护者确认"先降低对 Linux/macOS 的验证，等最终视需求再验收"；
  M0 收口报告中对应条目已改为"⏸ 延后"。
- 2026-10-08：**本 ADR 的第一条理由（配额）已因转公开而消失**（公共仓库的 Actions 额度不受限，
  macOS runner 的 10x 计费不再构成约束），维护者要求把 macOS 补进发布链路。据此做的修订：
  1. `release.yml` 新增 `build-macos`（macos-latest，`--target universal-apple-darwin`，
     一份 dmg + 一份 `.app.tar.gz` 覆盖 Apple Silicon 与 Intel），updater 清单写
     `darwin-aarch64` 与 `darwin-x86_64` 两份指向同一产物；
  2. 校验和与 GPG 签名**上移**到 `publish`：两平台产物合并后只签一份 `SHA256SUMS`；
  3. 官网按平台渲染（macOS 用户拿到 `.dmg` 按钮与 macOS 矩阵行），`pnpm check:site` 增加
     macOS universal 用例；
  4. macOS 仍走 **ad-hoc 签名**（红线 R5：不购买 Apple Developer 证书、不做公证）——
     "首次打开要多点一次"属已知现象，说明见下载页与 `docs/install/macos.md`。
  **仍然延后**：Linux（AppImage/deb/rpm 三套打包链 + 各自的真机验证），
  以及 macOS 的**真机安装与自动更新实测**（需要一台 Mac；首版无更旧版本可升级，随下一版补做）。
