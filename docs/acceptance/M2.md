## 4. 本阶段修复的缺陷

1. **审计快照断链（P1，产品语义错误）**：命令层所有 `audit::record` 的收尾硬编码
   `snapshot_id = None`——服务层打了快照、前端也拿到 id，唯独 `operation_records.snapshot_id`
   恒为 NULL，操作历史里"可否回滚"全是"否"。修复：`record_with` 从结果的 IPC 契约
   （camelCase `snapshotId`）提取并写入审计；stash / pull / cherry-pick / revert 的
   Outcome 结构补上此前被半路丢弃的 `snapshot_id` 字段（`docs/API.md` 已同步）。
   顺带：`stash_drop` / `stash_clear` 的审计 args 现在带被丢 oid 清单（gc 前自救线索），
   `git_fetch` / `git_pull` 补上了此前缺失的审计记录（与 `git_push` 对齐）。
2. **历史图 ref 胶囊全空（P1，用户可见）**：libgit2 引擎的 log/show 不装饰 refs
   （契约记录在案，但图页是唯一受害者）。修复：`RefDecorations`——一次引用枚举
   （O(引用数)，<1ms）建 `oid → token` 表，token 形状与排序模仿 `%D`
   （`HEAD -> main` / `tag: v1` / `origin/main`）；差分测试从"断言 libgit2 refs 为空"
   翻转为"两侧排序后 token 序列相等"，`docs/GIT-ENGINE-DIFF.md` 同步移出不对称表。
3. **stash 展开崩溃（P1，崩溃）**：后端 `Option<DiffReportDto>` 序列化为 `untracked: null`，
   前端用 `!== undefined` 判断——展开任何**无未跟踪文件**的 stash（常态）都会把整个
   状态页炸进错误边界。由新增 E2E 抓到（T2.8 时无 stash E2E 所以漏网）。
