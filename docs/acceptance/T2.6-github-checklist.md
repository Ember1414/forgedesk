# T2.6 远端同步：真实 GitHub 联调检查表

> 自动化测试（`crates/services/tests/sync.rs`、`e2e/sync.spec.ts`）用**本地 bare 仓库**
> 当远端，走的是 git 同一条 receive-pack / upload-pack 路径，因此覆盖了编排、
> 结构化解结果、冲突现场、拒绝分类、取消与前端交互。
>
> 只有真实远端的这几件事它验证不了：**认证**、**真实网络与代理**、
> **GitHub 侧的真实拒绝文案**。这份检查表就是为它们准备的——请在**有网机器**上跑，
> 预计 20–30 分钟。

---

## 1. 前提与安全约定

| 项 | 要求 |
| --- | --- |
| 测试仓库 | 一个**一次性**仓库（新建的空仓库即可），**不要**用任何你舍不得的仓库 |
| 破坏性用例 | 第 7 项会改写远端历史 —— 只在一个**一次性分支**上做，做完删掉该分支 |
| 账号 | 用 HTTPS 即可（凭据库在 T2.7 落地；本任务只需要 git 能拿到凭据） |
| 环境 | 桌面应用已启动（`pnpm tauri dev` 或已构建的安装包），能打开这个仓库 |
| 记录 | 每个用例记「实际观察」；失败时附日志（设置 → 高级 → 打开日志目录） |

> ⚠️ 本任务**不**要求真实联调通过才能验收；这份表是"把只有真实环境能暴露的问题
> 带回来"的手段。任何一栏失败都是**有效产出**，请原样记录，不要绕过。

---

## 2. 检查项

前置：用应用克隆或打开测试仓库，确认顶部出现**同步条**
（Fetch / Pull / Push 三个按钮 + 上游名 + 领先/落后）。

| # | 操作步骤 | 预期观察 | 失败时要留的证据 |
| --- | --- | --- | --- |
| 1 | 打开仓库，看上方的同步条 | 显示 `origin/main`；与远端一致时显示"与上游一致"；没有上游时显示"当前分支还没有上游" | 同步条截图；控制台 `__errs` |
| 2 | 点 **获取**（无远端变化） | 进度条一闪而过或直接结束；**不**弹任何错误；ahead/behind 不变 | 截图；日志里该次 `git fetch` 的 stderr |
| 3 | 在 GitHub 网页给默认分支提交一个文件，回应用点 **获取** | 落后计数 +1；点历史能看到远端新提交（`origin/main` 位置的 ref 胶囊） | 截图（同步条 + 历史页） |
| 4 | 点 **拉取**（策略"仅快进"） | 成功：落后归零，历史出现该提交；**快照页出现一条"同步前"快照**（红线 R7 的安全网） | 快照页截图；设置 → 审计里 `git pull` 记录 |
| 5 | 网页与本地**同时改同一个文件的同一行**，然后点 **拉取**（策略选"允许合并提交"） | 弹出"拉取产生了冲突"对话框并**列出冲突文件**；点"去解决冲突"跳到冲突页；仓库停在冲突状态（`git status` 可见 unmerged） | 对话框截图；`git status` 输出；冲突页截图 |
| 6 | 本地提交一个改动 → 点 **推送** | toast "已推送到 origin"；GitHub 网页上能看到该提交；ahead 归零 | 截图 + 远端提交页 |
| 7 | **（一次性分支）** GitHub 网页给该分支推一个提交；本地给同一分支做一个分叉提交 → 点 **推送** | 弹出"推送被拒绝"对话框，**三条**按钮：先拉取 / 覆盖远端（force-with-lease）/ 取消；点"先拉取"后再点"覆盖远端"能成功覆盖 | 对话框截图（三条按钮文案）；两次 `git push` 的参数（日志/审计） |
| 8 | 本地建一个新分支，给它提交一次 → 点 **推送** | 带 `--set-upstream` 推送（不报"当前分支没有上游"）；推送后分支页该分支显示 upstream 徽标 | 分支页截图 |
| 9 | 用**私有**仓库 + 故意无效的凭据（例如系统凭据里存了一个已撤销的 token）→ 点 **获取** | 失败但**不挂住**（`GIT_TERMINAL_PROMPT=0`），错误码 `AUTH_REQUIRED`/`AUTH_EXPIRED`，提示指向设置里的账号配置；**日志里不出现 token 原文**（红线 R8） | 错误提示截图；日志片段（确认已脱敏） |
| 10 | 拔网 / 把系统代理指到 `127.0.0.1:1` → 点 **获取** | 错误码 `NETWORK`，提示检查网络与代理；应用不崩、同步条可再次点击 | 截图 |
| 11 | 打开一个**大**远端仓库的 fetch，在进度条跑动时点 **取消同步** | 任务停止；**不弹红色错误**（取消是用户的决定）；本地与远端都没有变化 | 截图；远端 `git log` 未变 |
| 12 | 复查留痕：设置 → 审计历史 / 仓库的快照页 | `remote.add`、`git pull`、`git push` 都有审计记录；pull 之前有 `pre-sync` 快照；`push` 的记录里**没有**裸 `--force` | 审计页截图 |

## 5. 与自动化测试的关系

| 能力 | 自动化（本地 bare 远端） | 本检查表（真实远端） |
| --- | --- | --- |
| fetch / pull / push 的结构化结果（`updates` / `merge` / `rejections`） | ✅ | 抽样确认 |
| 冲突现场与冲突文件清单 | ✅ | ✅ |
| non-fast-forward 拒绝 → `PUSH_REJECTED` 三条修复路径 | ✅ | ✅（真实文案） |
| 断网（不可达远端）→ `NETWORK` | ✅（`127.0.0.1:1`） | ✅（拔网 / 代理） |
| 取消 → `CANCELLED` 且远端零改动 | ✅ | ✅ |
| 认证失败 → `AUTH_REQUIRED` | ⚠️ 本地远端不需要认证 | ✅ |
| 审计与 `pre-sync` 快照留痕 | ✅（服务层测试） | ✅ |
