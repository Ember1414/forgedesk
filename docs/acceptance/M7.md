## 5. 遗留与后续

- **T7.4 未做的部分**：只剩**文件关联**。协议注册（`forgedesk://`）早在 T0.11 就随 NSIS 钩子落地（含卸载清理）。
  文件关联之所以留白：桌面 Git 客户端没有公认的"关联对象"——把 `.gitignore` 关联到某个 Git 客户端会改变用户在
  编辑器/资源管理器里的既有习惯，而"双击打开仓库"在 Windows 上是目录而非文件类型，做不成关联。
  因此这一项应当**由需求驱动**（真有用户要求时再定关联什么），而不是为了打勾而加。
- **GPG 公钥的随站发布（2026-10-08 闭合）**：此前 `/updates/gpg-pubkey.asc` 从未有文件——下载页探测失败，
  GPG 入口永远隐藏，页面上只剩"公钥尚未随站发布"的说明（v1.0.0 上线后实测发现）。
  现在公钥的真相源是 `docs/keys/forgedesk-release.pub`（本次导出，指纹
  `41A6 22CA 5114 FB00 CE8A 9B98 B550 BA51 AD37 851B`），由 `build-site.mjs` 在构建时复制到站点路径；
  `pnpm check:site` 会断言两份逐字节一致、且源缺失时站点不得残留旧副本（轮换安全）。
- **平台暂缓**：macOS / Linux 的安装与更新真机验证推迟到 M8（ADR-005）。CI 矩阵与打包 targets 保留。
- **e2e 与 nightly**：仓库转公开后已恢复/启用（`e2e.yml` 手动触发、`nightly.yml` 定时）。
- **供应链**：`pnpm check:workflows` **0 警告**（7 个工作流，`uses:` 全部固定 SHA），OPEN-SOURCE-READINESS 的 C-1 闭合。
- **转公开门禁 A 组已执行**（2026-10-07）：A-2 / A-3 / A-5 / A-6 通过、A-1 以特征式替代通过；
  `docs/adr/ADR-004` 中回显的个人邮箱已脱敏（历史侧处置由人类决定）。详见 `docs/OPEN-SOURCE-READINESS.md` §4。
- **B-10（干净环境可复现）**：需在未参与开发的机器上照 `CONTRIBUTING.md` 走一遍。
- **官网的校验和直显**（原计划 M8·D8.4，已提前落地）：发布流水线把 `SHA256SUMS` 放到站点同源路径，
  页面展开 `<details>` 直接显示产物哈希，并与静态校验步骤并存。

## 7. 结论

**M7 已出口。** 首个正式版 `v1.0.0` 于 2026-10-08 发布：打 tag 后流水线自动完成
"版本/tag 一致性检查 → Windows 构建与签名 → 归一化命名 + 便携版 + 校验和 → GPG 签名 →
创建 Release → 生成并部署更新清单"，用户在下载页能拿到产物、校验和与（随站发布的）GPG 公钥，
应用内的自动更新对着同一份清单工作。

"首个版本没有更旧版本可作升级起点"（等 1.0.1）与"安装形态需要真机"（§4 第 1 项），
