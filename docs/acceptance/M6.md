## 4. 待人类在目标平台执行的清单

1. **Linux**：无 Secret Service 环境（如裸 WM）验证凭据回退到加密保险库可创建/解锁/保存/读取；
2. **Linux**：inotify 上限低的内核上验证 watcher 降级轮询与提示；
3. **macOS**：LaunchAgent 自启启用→重启→关闭；Keychain 凭据读写；
4. **Windows**：注册表自启（HKCU Run）启用/重启/关闭；Toast 通知真实弹窗（需 T7 打包 AUMID，当前日志兜底）；
5. 三平台手动走一遍：开发者模式安装示例插件 → 授权 → 启用 → 撤销权限 → 确认插件调用失败且宿主正常（自动化已覆盖同链路的 UI 测试与 Rust 状态机测试）。

## 5. 遗留与后续

- **git_commit 宿主调用**：刻意返回结构化错误——让插件直接创建提交需要"快照所有权/审计归属/UI 标注"三处跨层设计（红线 R7 不绕过）；待提交钩子出现真实插件需求再评估；
- **自定义 Provider 扩展点**：两个内置 Provider 已覆盖 GitHub 且共享 HTTP 底座；规格本身标注为高级扩展，待有真实第三方平台需求再立项（避免无消费者的 API 过早冻结）；
- `can_block` 阻断授权 UI：宿主结构上不支持阻断（安全默认），管理页授权 UI 属后续迭代；
- `check:colors` 已入 package.json，CI wiring 待 T7.2 的门禁清单化时一并列管。
