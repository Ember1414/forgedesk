## 5. 需要人类执行的三平台验收（唯一未闭合项）

1. **macOS / Linux 终端实测**（对应验收第 2 条）：
   `cargo run -p forgedesk-services --example pty_spike`
   期望：9/9 checks passed（bash/zsh 路径；emoji 用 printf `\U0001F389`）。
   已知预期差异：Unix 上 ctrl-c 走 SIGINT（外部命令 sleep 必中断）；DSR 应答仍需要。
2. **终端手工冒烟**（每平台一次）：应用内打开终端 → `echo 中文 🎉` → 中文/emoji 正常；
   `git rebase -i` 出现解释卡（引导走冲突向导）；`git reset --hard` 出现提示条；
   Ctrl+C 取消长命令；Ctrl+F 搜索；右键菜单全项可用。
3. **审批确认**（不阻塞合入，但需要拍板）：
   - T5.3 默认拦截级别保持"提示级"（确认级默认关闭）；
   - 补偿快照默认开启；
   - PS 内建 cmdlet 的 Ctrl+C 限制是否可接受（备选：终端加"停止"按钮直接 kill 进程组）。

## 6. 缺陷与后续

- 本轮修复的关键缺陷（均在交付前）：ConPTY 输出管道需先释放 master 才 EOF（退出事件丢失）、
  PSReadLine 的 DSR 启动等待（无头端必须应答）、命令面板快捷键与输入框的竞态
  （INPUT/TEXTAREA 聚焦时跳过分发）、外部修改检测的 ref-in-render。
- 后续建议（非阻塞）：① blame 5000 行 <2s 的自动化计时基准（当前为人工推断）；②
  终端加"停止"按钮（kill 进程组）作为 Ctrl+C 的平台差异兜底；③ `git rebase -i`
  触发时在提示条中加"打开冲突向导"直达按钮。
