# 桌面错误与自动更新修复（2026-11-22）

用户反馈登录、GitHub 或插件页出现未知错误。本轮查看本机桌面日志，发现四次前端未捕获错误，
内容均为 `null`，没有操作来源。因此不能把所有历史弹窗归结为同一原因。
以下分别记录已复现的问题、实际修复与验证边界。版本号仍为 `1.1.4`，没有覆盖既有 Release。

## 已复现与修复

| 问题 | 证据 | 修复 |
| --- | --- | --- |
| 登录事件订阅失败没有被接住 | 拒绝 `job:done` 订阅会产生未处理 Promise；关闭时再次对原 Promise 调用 then 仍无 catch | 统一等待订阅结果、处理失败并清理监听；失败在弹窗内显示操作来源 |
| 快速完成的登录任务丢事件 | 任务在 `jobId` 返回前完成，原界面一直等待 | 先订阅再启动；身份返回前暂存有界终态事件；关闭时取消任务，下次打开重建表单 |
| 未知错误缺少排查信息 | Tauri 可以抛出 `null` 或字符串；错误提示只显示 detail，原始 message 没有出口 | IPC 保留操作名；结构化错误保留 code；提示在 detail 缺省时显示 message；错误格式化支持循环引用和 BigInt |
| 登录弹窗内看不到错误详情 | 浏览器命中测试发现全局 Toast 被模态遮罩挡住 | 登录弹窗内提供错误与详情；通用错误面板的 details 标签接入中英文文案 |
| 错误日志字段重复 | tracing 的事件 message 与显式 message 同名，生成重复 JSON key | 显式错误字段改为 error_message；IPC 失败每会话最多记录 20 次，不记录参数，日志失败不递归 |
| 更新进度倒退/长期很低 | 更新插件 `on_chunk` 传入的是本块大小，原代码当成累计大小 | 后端累计字节；单测及真实下载验证单调增长并达到总量 |
| 未验签就显示正在安装 | 插件的下载完成回调先于验签 | 拆为 download（内含验签）与 install；验签通过才发 installing 事件 |
| 更新失败原因混为网络错误 | 验签、磁盘权限、安装器格式都映射 NETWORK | 分离 UPDATE_SIGNATURE_INVALID / UPDATE_INSTALL_FAILED，保留详情和重试路径 |
| 更新无并发保护、无显式超时 | 两次调用能同时进入下载/安装；插件 check 返回 Update 时清空 timeout | 单一安装锁；检查 15s、连接 10s、读取 30s、下载 300s；失败释放锁 |
| 更新没有使用界面代理设置 | 原路径直接调用 app.updater() | 检查与下载接入直连/系统/手动代理及 bypass |
| macOS/Linux 更新后未重启 | 插件文档与源码明确要求应用自行 relaunch，原命令成功后直接返回 | 非 Windows 平台主动重启；Windows 安装器仍负责重启，退出前清除会话标记 |
| 手动更新入口与跳过状态不完整 | 关闭自动检查后设置页没有手动检查入口；“稍后”永久遮住本次会话后续新版本 | 设置页手动检查、共享缓存、单一后台计时、发布说明；稍后只针对当前版本；计划过期重新检查 |
| 签名没有强制绑定清单版本 | 默认只验证文件签名，未开启插件的 requireSignedVersion | 发布配置启用版本绑定；线上 Windows/macOS 的 1.1.4 签名已含匹配版本 |

更新前如果编辑器有未保存草稿，界面会阻止安装并提示先处理文档，避免主动重启丢掉当前会话草稿。

## 原生桌面验证

Windows release 构建使用独立应用身份、临时数据和本地 HTTP 服务。一次性测试密钥仅生成在忽略目录，
验证后删除私钥；不使用真实发布私钥。测试数据不是可执行安装器，不会替换用户应用。

- 真实 `update_check` 读取版本与说明；非法版本被拒绝、过期版本返回 PLAN_STALE。
- 640,000 字节数据经 22 个分块事件累计到 640,000；篡改一个字节返回 UPDATE_SIGNATURE_INVALID，未发 installing。
- 有效的 9.9.9 签名配上 9.9.8 清单被拒绝。
- 下载期间第二个安装调用被拒绝；前次失败后可重试。
- 正确签名的数据通过验签，随后因为它不是安装器返回 UPDATE_INSTALL_FAILED，证明两阶段错误得到区分。
- 真实 GitHub IPC 未登录时为 AUTH_REQUIRED，缺少插件为 NOT_FOUND，三个内置插件可列出。
- 登录窗口能订阅、关闭与重新打开，未提交的 PAT 草稿不残留；未登录访问 PR 显示登录引导，未捕获错误为空。

拒绝订阅的故障注入另由[登录单测](../src/features/settings/AccountsPanel.test.tsx)及
[浏览器 E2E](../e2e/github.spec.ts)覆盖；原生宿主的 invoke 不可直接替换，未将该浏览器故障注入当作原生 IPC 失败。

原始日志、截图及机器可读结果位于本机忽略目录 `target/desktop-updater-20261122/`。

## 验证边界与后续

- 没有将有效安装器安装到用户系统，没有宣称完成跨版本升级和回滚验收。
- macOS/Linux 重启路径完成代码修正，仍需真实设备验证；便携版与安装版的安装位置差异也需单独验收。
- 自动更新这次仍使用现有安装方式，下载取消、断点续传、完整升级回滚继续保留为后续事项。
- 历史四次 null 错误缺少来源，无法事后逐条归因；新增来源日志用于区分未来不同操作的失败。
- 本轮不新增依赖，不更改产品功能范围；API 与错误码变更已同步到[契约](API.md)。
