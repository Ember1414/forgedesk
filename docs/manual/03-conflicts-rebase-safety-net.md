# 03 · 冲突、Rebase 与安全网

ForgeDesk 的三个"记忆点"能力都在这里：三栏冲突向导、拖拽式 rebase、快照回滚。

## 三栏冲突解决向导

merge / rebase / cherry-pick 产生的冲突都进入同一个「冲突」页：

- 左（本地 ours）、中（结果）、右（远端 theirs），顶部可切换到 base 视图；
- 每个冲突块提供四个动作：**采用本地 / 采用远端 / 两者保留 / 手动编辑**；
- 已解决的块折叠为绿色；可"跳到下一处未解决"；
- 底部固定操作条：**保存并标记已解决 / 标记已解决 / 中止操作**；
- 结果是写回文件后 `git add`；若仍有未解决块，禁止 continue 并高亮提示。

二进制冲突（图片等）提供"选择一方 / 手动替换"的专门路径，不会崩溃。

## 拖拽式交互 Rebase

从历史图框选提交区间 → 打开 rebase 面板：

- 列表可**拖拽排序**，每个提交可设为 **pick / reword / squash / fixup / drop / edit**；
- 右侧**实时预览**新历史，执行前可随时取消；
- 执行是**逐步**的：遇到冲突跳转到三栏向导，解决后继续；支持暂停、跳过、中止。

计划在生成时就校验合法性（例如不允许把全部提交 drop 掉）；执行前自动打快照。

## 快照与一键回滚（安全网）

所有**破坏性操作**（reset --hard、rebase、clean、checkout -f、stash drop 等）执行前
都会自动创建**快照**：

- 快照包含 HEAD、索引锚点，以及**未跟踪文件的内容备份**（受磁盘配额保护）；
- 「快照」页展示用量，支持手动打快照、清理与还原；
- 还原前会做**仓库指纹校验**，分阶段还原，并给出还原报告；
- 回滚后校验 HEAD / 索引 / 工作区一致性，**绝不"静默半成功"**。

## 操作历史

「操作历史」页是一条时间线：每条记录含操作类型、参数摘要、结果、耗时，
若留有可回滚的快照则提供**一键回滚**按钮。可按类型筛选、只看危险操作、按关键词搜索。
状态栏常驻显示当前是否存在可回滚点。

> 审计记录只读且已脱敏；导出见「设置 → 高级」的审计面板（JSON / CSV）。
