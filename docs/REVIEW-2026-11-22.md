## 确认的问题与处理

| 问题 | 复现与根因 | 处理 |
| --- | --- | --- |
| 日志会话被不必要地重启 | 同一 owner/repo/jobId 的 target 对象重新创建，effect 的 `[target]` 依赖触发取消和重新下载 | effect 依赖任务身份字段；重渲染保留原日志与下载 |
| 日志突发引起重复更新 | 分别派发 30 个 chunk，React Profiler 记录 30 次提交；每次 append 还复制累计数组 | 环形缓冲写入，每 50ms 发布一次快照；完成/取消/失败立即刷新最后一块 |
| 虚拟列表掩盖内存增长 | 20,005 行仍全部进入累计数组；虚拟化仅限制 DOM | 最多保留最近 20,000 行及 4,194,304 个 UTF-16 code unit，单行最多 16,384；显示截断提示并保留远端累计行数 |
| 早到事件可能绕过缓冲上限 | jobId 返回前原本用闭包无界保存完整 chunk | 同时限制早到队列的文本与事件数，溢出同样提示；关闭清理队列、定时器与监听 |
| 首屏携带未使用功能 | 路由静态导入终端、GitHub、插件等；生产主入口约 1.94 MB | 使用既有 React Router 路由级 lazy，保留常用入口；直接进入延迟页面显示本地化加载状态 |
| 小窗口日志可用区域不足 | 日志固定 420px，高度没有对话框与视口上限 | 对话框与日志区受视口约束，保持滚动及关闭按钮可达 |
| 列表缺少稳定键 | 浏览器记录 PR 文件列表与工作区分组的 React key 警告 | 按文件路径、分组名称提供 key |
| 浏览器预览额外请求 404 | 未声明 favicon，浏览器请求不存在的 `/favicon.ico` | 使用已有原创应用图标，由 Vite 打包 |

## 量化证据与边界

Windows 本机、同一生产构建目标 `TAURI_ENV_PLATFORM=windows`：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 主入口 JavaScript | 1,935.14 kB | 1,048.71 kB，减少约 45.8% |
| 主入口 gzip | 556.50 kB | 313.06 kB |
| 30 个独立 chunk 的 React 提交 | 30 次 | 50ms 刷新前 0 次，刷新时 1 次 |
| 20,005 行输入后的保留行数 | 20,005，无提示 | 20,000，有提示，总行数仍为 20,005 |

主入口大小不等于首屏全部资源，也不等于实际桌面启动时间。
另用 Edge 加载生产构建确认：仪表盘首屏实际加载 JS 合计 1,240,871 字节，
其中没有终端、编辑器或 Actions 页面块；随后切换 Actions 可正常加载对应页面。
该总量仅有修复后的测量，不用于声称同比下降比例。

960×600 的生产页面中，日志对话框坐标为 `(96, 62)`，尺寸 `768×476`，
20,005 行输入只挂载 26 个日志 DOM 行，最后一行可滚动到达，关闭按钮可操作。
`window.__errs`、浏览器 pageerror 与控制台 error 均为空。
本次使用 IPC 夹具验证真实前端与生产分块，没有访问真实 GitHub 账号或对远端写入。

字符串上限按 UTF-16 记账：保留正文最多约 8 MiB；早到队列另有同等正文上限。
这不等于进程堆上限，瞬时 IPC 字符串、快照、数组、框架和浏览器都有额外开销。
大块截断会复制保留尾部，避免小的 sliced string 继续引用整个旧块。
